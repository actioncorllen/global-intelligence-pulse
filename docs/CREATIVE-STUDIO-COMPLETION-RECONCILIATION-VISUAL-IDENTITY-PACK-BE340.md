## 2. BUILD 1 delivered — Product Visual Identity Pack (keystone, preview commit `0cad104`)
The defining requirement is **product visual consistency**, and the one genuinely-missing foundation was a structured identity pack. Built, reusing the two existing authoritative readers, **never inventing**:
- **Reader** `fetchProductVisualIdentityPackSources(productId, market)` (`src/lib/commerce/commerce-actions-api.ts`, +89) — composes `fn_product_identity_resolution` + `fn_product_commercial_asset_readiness_owned`, fail-closed to nulls. Existing readers unchanged.
- **Pure assembler** `src/lib/creative-studio/product-visual-identity-pack.ts` (new, 122 lines): `buildProductVisualIdentityPack(sources)` → each attribute `{ value, source, confidence: HIGH|MEDIUM|LOW|UNVERIFIED }`. Canonical identity, SKU/variant and category carry values + source + confidence **only** when the server data supports them; **brand, model, primary/secondary colour, body shape, proportions, materials/finish, controls/ports, accessories, dimensions, functions, visual constraints, never-invent features are all reported `UNVERIFIED` / "Not verified"** — there is no structured source for them, so they are **never fabricated or parsed from the title**. Includes `images` summary, `rightsEligibility`, a deterministic content-hash `identityVersion` (over the verified attributes only, so a generated asset can be associated with the exact identity version used), `verifiedAttributeCount`, and `hasAuthorisedReferenceImage`.
- **Display** `src/components/commerce/product-visual-identity-panel.tsx` (new) — a read-only "Product Visual Identity" panel in the real Explorer detail (reusing the BE337/BE338/BE339 ExplorerDrawer), each row badged **Verified · <confidence>** or **Not verified**, plus images summary, authorised-reference status, and identity version. **Display-only: it feeds no commerce/creative/generation gate.**
- **Tests:** 3 assembler unit tests (SharkNinja CONCEPT_ONLY → LOW identity, no SKU, all visuals UNVERIFIED, no authorised image; e453 IDENTITY_RESOLVED → HIGH identity + SKU, visuals still UNVERIFIED i.e. never invented; identityVersion stable + changes with verified inputs) + a real-ExplorerDrawer render test (panel shows "Not verified" for colour/materials). **Full suites 165/165 across 21 files; typecheck clean; build OK.**

**Why this is the right keystone:** it makes explicit, per attribute, what is verified vs unknown. Because the only verified visual facts are identity/SKU/category (not shape/colour/materials), it proves that **true visual consistency must come from an authorised reference image + Product Asset Lock, not from invented specs** — which is exactly the founder's "do not invent missing specifications" + "features that must never be invented" requirement, enforced by construction.

**Authoritative server-side pack (prepared design, NOT applied — needs a production deploy, which is not approved here):** a `product_visual_identity_pack` table (tenant_id, product_id, market, identity_version, attributes jsonb, source+confidence per attribute, created_at) + an assembler function `fn_product_visual_identity_pack(product_id, market)` (SECURITY DEFINER, owner-scoped) + recording `identity_version` on `commerce_generated_assets` at generation time so every asset is associated with the exact identity version used (BUILD 1 "version the identity pack and associate generated assets"). This is the next step for the backend, to apply under a future controlled-production-deployment approval; the frontend assembler already mirrors its contract.
