# Strateloq — Product Discovery Release & Rollback Runbook (W0.07)

_2026-11-18. Covers migrations, regression execution, database rollback, feature rollback, and failure
response for the zero-credit Product Discovery backend. No paid provider calls; the release gate is
deterministic, call-free and zero-residue._

## 1. One-command release gate
Run as **service_role** (SQL editor / migration context):
```sql
SELECT public.fn_pd_release_verification();   -- all_green must be true (16 areas)
```
- Deterministic (each fixture suite runs in a rolled-back subtransaction) → **zero residue**, repeatable.
- Call-free: `discovery_runs` count is unchanged; `provider_calls = 0`.
- Returns `{all_green, failed, results:[{area, pass, ...}]}`. **Do not release if `all_green=false`.**
- Covers: identity/dedup, ad-origin safeguards, country-specific scoring, UNKNOWN safeguards, supplier/landed-cost, asset lock/image rights, rights-gated publication (all FALSE), entitled browse/adopt, research reserve/settle/refund wiring, cross-tenant/market isolation, provider-budget enforcement, 18-market provider states, disabled-adapter rejection, emergency stop, failure recovery, service_role-only access.

### Component suites (run individually if a group fails)
```sql
SELECT public.fn_stage1_early_opportunity_selftest();      -- identity/dedup/UNKNOWN/isolation (+fastmoss/kalodata/invariants/bridge)
SELECT public.fn_w004_opportunity_scenarios_selftest();    -- A–J opportunity scenarios (self-cleaning)
SELECT public.fn_product_image_selftest();                 -- asset lock / image rights
SELECT public.fn_fastmoss_commerce_adapter_selftest();     -- FastMoss adapter
SELECT public.fn_kalodata_commerce_adapter_selftest();     -- Kalodata adapter
SELECT public.fn_discovery_orchestrate_plan('<tenant>');   -- 18-market plan (read-only)
```
**Do not run two stateful fixture suites in the same statement** — some nested suites write `is_fixture=true`
rows and are non-idempotent; run them one at a time, or via `fn_pd_release_verification` (which isolates each).

## 3. Database rollback
All changes are function/grant/additive-table level. To roll back:
- **Function behaviour**: redeploy the prior `CREATE OR REPLACE FUNCTION` body (previous migration) — no data migration needed.
- **New tables** (`discovery_orchestration_control`): `DROP TABLE public.discovery_orchestration_control;` (only removes the emergency-stop flag; drivers then treat stop as disengaged).
- **New column** (`commerce_research_run.reservation_id`): safe to keep; to remove, `ALTER TABLE public.commerce_research_run DROP COLUMN reservation_id;` (metering then no-ops).
- **Grants**: the hardening migrations only *revoked* `anon/authenticated`. To restore (not recommended), `GRANT EXECUTE ... TO authenticated;` — but these functions take an explicit tenant and must stay service_role-only.
- **Fixture residue**: `DELETE FROM public.product_opportunity_decisions WHERE is_fixture=true; DELETE FROM public.product_market_competitors WHERE is_fixture=true; DELETE FROM public.product_market_evaluations WHERE is_fixture=true;` (never touches `is_fixture=false` real data).

## 4. Feature rollback / kill switches (no redeploy)
- **Halt all acquisition instantly**: `SELECT public.fn_discovery_emergency_stop(true,'incident');` → drivers refuse (`EMERGENCY_STOP`), no outbound call. Resume: `fn_discovery_emergency_stop(false,'resolved')`.
- **Close provider budgets**: a metered provider with no active `provider_call_budget` fails closed. To revoke an open budget: `UPDATE public.provider_call_budget SET active=false WHERE active;`
- **Disable an adapter/market**: `UPDATE public.discovery_provider_market_config SET enabled=false WHERE provider=? AND market=?;` (all advertising/eBay adapters already `enabled=false`).
- **Block publication**: catalogue publication is gated on `catalogue_source_rights.display_derived_cleared` (all FALSE). Set a provider's flags FALSE to withdraw its cards at read time.
- **Refund stuck research reservations**: `SELECT public.fn_research_meter_reaper(500);` (refunds abandoned RESEARCHING runs; settles completed).

## 5. Failure response (by release-gate area)
| Failing area | First action |
|---|---|
| 1 identity/UNKNOWN/isolation | run `fn_stage1_early_opportunity_selftest` alone; if a nested suite fails, run it alone; check for `is_fixture=true` residue and clean |
| 3-5 opportunity A–J | run `fn_w004_opportunity_scenarios_selftest` and read per-scenario `pass`; a confidence/band change → re-check `pod_evaluate` |
| 7 rights FALSE | a provider flag was set true without sign-off → set it FALSE; investigate who changed it |
| 9 metering wired | re-apply the metering wiring migrations |
| 11 budget / 12-13 plan / 14 emergency / 15 recovery / 16 grants | an infra invariant regressed → re-apply the relevant orchestration/hardening migration; confirm emergency_stop, no active budget, no anon/authenticated grants |
| 16 service_role-only | a sensitive function was granted to anon/authenticated → `REVOKE EXECUTE ... FROM anon, authenticated;` |

## 6. Pre-launch invariants (must all hold before any live test)
- `fn_pd_release_verification().all_green = true`
- Emergency stop **disengaged** but reachable; 0 active provider budgets; all advertising/eBay adapters `enabled=false`.
- All `catalogue_source_rights` dimensions FALSE (no publication).
- Advisors: 0 ERROR.
- Real-data GOLD benchmark is a **separate** acceptance (needs live provider data + approved pilots) — a green gate here does NOT imply GOLD.
