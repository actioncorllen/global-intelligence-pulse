# STRATELOQ — Published Storefront Parity (public URL rendered wrong / legacy contract)

**Status:** `PASS_REPUBLISH_REQUIRED` (backend + edge function fixed; the already-live
Nightlight must be republished by the merchant to pick up the corrected canonical render).

## Root cause — two independently-generated representations

- **Builder preview** consumes the live claim-safe strategy `fn_product_page_strategy` v3
  (`evidence_gated_claim_safe_v1`) via `fn_product_page_builder_context`.
- **Published public page** = edge function `storefront` → `fn_public_storefront_render(slug)`
  → rendered a **stale, separately-generated `page_model`** stamped
  `deterministic_claim_safe_generator_v1`, which still contained the suppressed/unsupported
  strings ("Transparent estimated delivery", "New condition, fulfilled from the supplier
  warehouse", delivery/condition FAQ), empty product-noun placeholders, null price and a
  "Draft store (not published)" announcement.
- The edge function additionally **hardcoded** a `Preview storefront — … test listing` banner
  on every page and a `New condition. Delivery times are estimates…` footer claim; and
  `fn_public_storefront_render` hardcoded a `product_provenance` condition/fulfilment block.

So preview ≠ published because they were never a single contract.

## Fix (reuse the existing strategy; no second architecture) — mig_340 + edge v16

1. **Single canonical contract, captured immutably at publish.** `fn_storefront_publish` now
   builds an immutable `runtime_contract.published_spec` (+ `published_revision_id`) from the
   SAME source the preview uses (`fn_product_page_strategy` v3) plus the rights-cleared
   supplier asset (Product Asset Lock), merchant selling price and market. Preview and
   published spec are now generated by one engine.
2. **Public renderer serves only the immutable snapshot.** `fn_public_storefront_render` reads
   `published_spec` (render_mode `CANONICAL_PUBLISHED_SNAPSHOT`); the stale `page_model` and the
   hardcoded `product_provenance` are gone. A legacy page published before this fix (no
   snapshot) renders a **minimal claim-safe** page (no stale strings) with
   `render_mode=LEGACY_MINIMAL_NEEDS_REPUBLISH` and `needs_republish=true`.
3. **Edge function (`storefront` v16).** Removed the always-on "test listing" banner (a
   genuinely PUBLISHED customer page shows none; noindex stays via `X-Robots-Tag` + meta only).
   Removed the hardcoded condition/delivery footer claim. Renders the approved Overview
   (problem/solution) and Product details sections. Checkout stays the safe disabled
   "Checkout coming soon" state. CORS, security headers and `verify_jwt=false` (public
   read-only) preserved.

Nothing was auto-published or auto-republished. The write-path proof runs in a rolled-back
subtransaction.
