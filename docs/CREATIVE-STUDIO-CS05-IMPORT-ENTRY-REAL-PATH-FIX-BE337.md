## TASK 1/2 — Diagnosis of the real production runtime + complete render path (source-grounded on the deployed commit)
The deployed commit `df1e2f6` IS production, so its source is authoritative. Tracing `src/routes/workspace.tsx` → the ecommerce path:

`/workspace?view=opportunities` → `WorkspacePage` → `WorkspaceIntelligence` → `ReadyWorkspace` (isEcommerce) → `visibleSection==="opportunities"` → **`OpportunitiesSection(isEcommerce=true)`** (`workspace-sections.tsx:1923`) → **`EcommerceWorkspaceSection view="decisions"`** (`:1933`) → **`ProductsBody`** (`ecommerce-workspace.tsx:2041`) → **`ProductExplorer`** (the default "My research" source, `:1535`) → open a product → **`ExplorerDrawer`** → its `actions` = **`ProductCommerceActions` at `product-explorer.tsx:1179`**, mounted with **`concreteProductActionsAllowed={false}` and NO `allowImageImport`**.

**Root cause:** BE335/BE336 added `allowImageImport={true}` to a **different** `ProductCommerceActions` mount — the `ProductDecisionCard` drawer at `ecommerce-workspace.tsx:650` — which the `?view=opportunities` route **does not render**. The founder's actual detail (the ExplorerDrawer, mount 1179) never received `allowImageImport`, so the standalone Import button was absent. This exactly matches the founder's live observation: the Explorer mount passes `concreteProductActionsAllowed={false}`, so `filterVisibleActions` yields only the fail-closed subset (Create Ad + Add to My Store) — precisely what the founder saw — and without `allowImageImport` the standalone Import button cannot appear. The previous isolated unit test rendered `ProductCommerceActions` directly with `allowImageImport={true}` hand-passed, so it never exercised the real mount wiring and could not catch this.

**Bundle/caching ruled out as the cause:** the public entry graph of production (`www.strateloq.com`, 45 `/assets/*.js` chunks) contains neither `"Import Product Image"` nor `allowImageImport` — because the authenticated workspace/commerce code is in **lazy, auth-gated chunks not reachable from the public landing graph** (consistent with BE334). So public-bundle grep cannot adjudicate the mount wiring, and this was not a caching/stale-bundle issue; it is a source-level wrong-mount defect, proven by reading the deployed commit's source. Owner permissions, route variants and responsive layout were also excluded: the failure reproduces structurally for any ecommerce member on this route.
